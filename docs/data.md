# 项目拆解数据结构

所有共享默认数据位于 `data/content.json`，界面和样式分别位于 `assets/app.js`、`assets/app.css`。不再把大段数据或图片内嵌在 HTML 中。

## 组成与支撑分别记录

| 集合 | 保存什么 | 如何连接 |
| --- | --- | --- |
| `projects` | 整个项目的名称、范围说明 | 项目 ID |
| `layers` | 品牌认知、组织逻辑、空间项目三层 | 层级 ID |
| `groups` | 各层下的分类，如品牌母题、行动计划 | 引用 `project`、`layer` |
| `objects` | 母题、叙事、行动、空间单元、产品、子项目或设施建议 | 引用分类 `group`；子项目用 `parent` 引用父对象 |
| `materials` | 可独立查看和修改的文字、任务、指标、条件、图件说明 | 用 `object` 指向一个管理归属；另附 `refs` 来源 |
| `links` | 不同内容对象之间的支撑关系与具体贡献 | 用 `source`、`target` 引用对象 |
| `sources` | 原始文件编号与名称 | 由素材引证引用 |

`parent` 表示组成关系，例如“情绪智能”包含透明工厂子项目；`links` 表示支撑关系，例如“打开前台”由透明工厂承担任务。支撑关系不用于自动更改内容树归属或汇总规模。

## 内容对象示例

```json
{
  "id": "DG-P01",
  "project": "dg",
  "group": "dg-projects",
  "title": "透明超级工厂",
  "description": "源子项目编号 2-2",
  "parent": "DG-PROD-02",
  "open": false
}
```

`open` 是首次访问时的默认展开状态，浏览者自己的展开状态优先。

## 素材示例

```json
{
  "id": "DG-P01-m1",
  "object": "DG-P01",
  "project": "dg",
  "title": "项目任务",
  "body": "透明生产线、参观走廊、模组演示及研学课程等任务。",
  "kind": "任务",
  "basis": "原文归纳",
  "refs": [
    {
      "doc": "B",
      "page": 30,
      "locator": "2-2 行",
      "quote": "支持该记录的原文片段或断行整理文本"
    }
  ]
}
```

- `kind`：文字、任务、指标、条件、图件。
- `basis`：明确区分原文摘录、原文归纳、图件归纳与研究归纳；加入口径提示的记录也明确标注。
- `page`：从1开始的 PDF 文件页序，不是印刷页码。
- `quote`：原文片段或断行整理后的依据说明，需与原页面配合核对。
- 图件类型的 `body` 是图件说明，实际图像由出处对应的页面预览提供；本版尚未自动裁切出独立图件文件。
- 图片文件为 `assets/previews/{doc}-{page}.jpg`。

## 维护约定

1. 对象和素材编号稳定且唯一；新增时不要复用旧编号。
2. 归纳后的核心叙事、行动与关系应注明整理性质，不作为原团队已确认结论。
3. 建设量、投资、设施规模保留各页口径，带上估算、建议、适用范围等条件；不自动合计。
4. 项目位置与具体实施任务分别记录；图示位置不替代正式用地或授权文件。
5. 一组对照图可以在同一对象下保留两份图件素材，避免丢失前后关系。
6. 移动素材只改变管理归属，不修改其原始来源，不自动推断新的支撑关系。
7. 新增数据或来源时，同步维护页面预览与 README 中的示例范围。页面计数从当前数据计算。

## 浏览器本地修改

新版存储键为 `urban-content-structure-v2`，保存项目、视图、展开状态和素材修改。旧版 `urban-content-demo-state-v1` 保留但不再读取，不自动迁移旧版修改。

共享默认数据与浏览者本地修改分开。验证新部署时可用无痕窗口，或在页面开发者工具中清除新版演示状态：

```js
localStorage.removeItem('urban-content-structure-v2');
location.reload();
```

“恢复整理稿”仅恢复当前素材，不清空其他素材的修改。浏览器存储不可用时仍可浏览，本轮修改仅在当前页面中保留。
