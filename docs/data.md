# 数据结构与内容维护

## 内容记录

当前记录内嵌在 `demo.html` 的 `const initial` 数组中。下面是简化结构，实际内容以源码为准：

```js
{
  id: 1,                         // 仓库内唯一、稳定的记录编号
  name: "记录名称",
  type: "产品策划",              // 产品策划 / 设施配置 / 图件说明 / 设计策略
  place: "所属节点或研究专题",
  text: "内容，以及口径、条件和必要说明",
  page: "32",                    // PDF 文件页序，从 1 开始
  doc: "B",                      // A / B / JZ，与 documents 对应
  project: "dg",                 // dg：东莞；jz：京张
  quote: "原文片段"
}
```

部分记录另有 `area`、`investment` 字段，保存本次提取的规模和投资。当前界面仍以 `text` 中的完整表述为展示内容，不使用这些字段进行计算或合计。

## 来源与页面预览

- `documents`：来源文件编号与文件名的对应关系。
- `previews`：页面预览图片，以“文件编号-页码”为键，例如 `B-32`、`JZ-391`。
- 图片为压缩的原 PDF 页面；原始 PDF 没有保存在仓库中。
- `quote` 可能经过断行整理，应与页面图像配合核对，不把自动提取结果当作版面原貌。

## 修改约定

1. 已有记录保持 `id` 稳定；新增记录使用未占用的编号。
2. 不把“建议”“意向”“估算”改写成已经落实的事实。
3. 指标的时间、范围、单位与限定条件应保留在内容中。
4. 更新正文摘要时，对照 `quote` 和页面图片；用户摘要与原文片段分别维护。
5. 新增或调整来源页时，同步维护 `documents`、`page` 和 `previews`。
6. 当前页面有固定数量和整理范围说明。增删记录时，同步更新 `index.html`、`demo.html` 和 README 中的数量与范围。

当前数据未进行全量口径统一，也不支持自动去重、数据汇总或指标计算。

## 浏览器本地修改

`demo.html` 使用 `localStorage`，键名为 `urban-content-demo-state-v1`。用户修改会覆盖本地显示，不改变 `initial` 数组。

维护人员检查新部署的初始数据时，可使用无痕窗口，避免历史本地修改覆盖新的默认内容。需要清除本地演示修改时，在该页面的浏览器开发者工具控制台运行：

```js
localStorage.removeItem('urban-content-demo-state-v1');
location.reload();
```

此操作仅清除当前浏览器、当前域名下的演示状态。
